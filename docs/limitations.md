# 한계·남은 검증·일일 운영 설계

## 실제 성공과 미검증 경계

Google 공식 RSS HTTP 수집 1회, 실제 항목10개, SQLite·압축 입력·Work 세션 LLM 편집·채널 파일 생성 성공. 테스트9개 통과. 별도 뉴스/Google 웹 화면과 독립 대조는 하지 않음. 수개월 안정성·전일 비교 실데이터·패션API·외부 LLM API는 미검증. SQLite와 원천 파일을 포함하여 결과 재생 가능.

Google RSS의 새 등장/사라짐은 관측 피드의 변화이며 관심 감소/실제 발생 종료/판매량 변화로 해석할 수 없음. 순서는 공식 순위가 아니므로 +순위 지표를 만들어내지 않음. 하루 한 번 관측이면 짧은 이벤트를 놓칠 수 있음. RSS에 없는 성장률과 active 상태는 null. RSS 과거7일을 채울 경로를 이번에는 검증하지 못하여 오늘부터 실제 이력 시작.

네이버는 패션 전체 자동 발견이 아닌 seed watchlist 모니터링. 현재 그룹5개는 아우터 중심이라 여성/남성/신발/가방 등 전체 분야 보고서가 아님. 공식 API를 통해 어제 종료 61일 구간을 받아 지표를 확보할 설계지만 실제 인증 호출을 해야 제공 범위/빈 값/반올림/갱신 지연을 확인할 수 있음. 낮은 지수의 큰 상대 증가율은 과장될 수 있으므로 관심량 유의성/원인 확인이라고 표현하지 않음.

## 정기 운영 구조 (설계만)

1. 로컬 cron/작업 스케줄러를 한국 고정시각에 실행. NOW 성공 경로부터 시작하고 API 인증 검증 이후 FASHION 추가.
2. 전체 run을 OS 파일 lock으로 보호하고 같은 날 중복 수집/중복 API 호출을 막음. **현재 runner에 lock/daily request budget은 미구현**이므로 사람이 하루1회 실행하는 PoC용. 수동 실행할 때마다 새 HTTP 요청 발생.
3. 수집기별 검증을 통과한 자료만 success로 저장. 403/429/timeout/인증오류 시 우회 금지, 재시도 폭주 금지, 실패 소스 표시. 현재 Google 오류는 실행 중단, NAVER 오류는 FASHION 실패 상태로 NOW 진행. 두 소스 모두 독립 실패 처리·구체적 HTTP 코드 기록은 정기 운영 전에 보완.
4. SQLite 트랜잭션 저장 후 동일 구간에서 계산. 실패/누락 날짜는 결측 처리. 과거7/30일 지표는 충족될 때만 표기.
5. 성공 소스의 핵심 관측만 LLM 입력. 이전 보고서 캐시 조건은 데이터 해시·모델·prompt 버전. 데이터 없는 날은 허구 보고서 생성 금지.
6. 외부 API 실패/거절/validator 실패 시 편집 출력을 발행하지 않고 deterministic 자료만 남김. 현재 편집 API 오류는 nonzero exit로 중단하며 DB/지표는 남음. 운영 단계에서 실패 run·검토 큐 기록을 보완.
7. 원천/지표/편집 파일은 날짜별 저장, 최초에는 사람이 검토. 같은 날 새 성공 실행은 해당 날짜 파일을 갱신하며 SQLite는 각 수집을 보존함. 원천 경로도 모든 run을 개별 파일로 보존하려면 날짜/시각 하위 폴더를 추가해야 함.
8. SQLite·원천 파일 백업, 정책 변경·API 버전·최근 quota 확인을 운영 점검으로 추가. AWS/대규모 queue 불필요.

## 검증 강화와 지표 한계

자동 숫자 검사·근거ID 참조·빈 신호 section 제한을 적용했지만 LLM의 인과 관계/정성 표현의 정확성은 완전 자동 보장 불가. 오늘 보고서는 비교 이력이 없음을 밝히고 sudden/persistent/new_entries/falling/linked를 비움. 최소 개수를 채우려 억지로 트렌드를 생성하지 않음.

실시간 인기라는 명칭 대신 **고정시각 공식 급상승 피드 관측**을 사용. Cross-source는 동일/alias 키워드의 실제 비교 가능 상승이 있어야 하며 현재 Google 값으로는 판정 불가. 가설과 활용 아이디어는 source fact와 구분. 검색 관심을 매출이나 사입 판단으로 바로 연결하지 않음. MONEY 확장도 투자 추천/예측 기능을 포함하지 않음.

## 운영 비용·사용 권리

RSS 공식 export 수집은 과금 API 사용 없음. Naver HUB 공지상 한시 무료이나 사용자 콘솔 조건·향후 정책 확인 필요. LLM API는 실제 키 등록 후 발생하며 입력6천/출력3천·기본모델 예시 $0.0072/일은 시나리오일 뿐. 이번 Work 편집 비용을 $0이라고 보고하지 않음. B2B 데이터 재판매·기사 전재 권리를 확인한 것은 아님.

다음 의사결정은 (a) HUB 키로 실수집 및 값 대조, (b)7일 같은 시각 RSS 수집, (c)실제 API 편집 한 번·비용·숫자 검증, (d)과장/원인 주장에 대한 사람 검토를 완료한 뒤 진행. 수익성·유료 구독 전환·고객 지불 의사는 이번 PoC 범위 밖.
